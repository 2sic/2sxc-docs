Raw Data Returned by DataSources

Warning

This is meant for people who want to contribute to the underlying source code of 2sxc and EAV.

If you only want to USE 2sxc / EAV, then you do NOT need this.

Most DataSources should return simple raw objects. 2sxc then converts these objects into entities for the query and the UI.

Tip

In most cases, create a small record which implements IRawEntityAutoConvert.

The APIs on this page were introduced as work-in-progress APIs for v22. The correct interface name is IRawEntityAutoConvert, not IRawAutoConvert.

The Normal Way: IRawEntityAutoConvert

Create a record containing the values the UI needs:

using ToSic.Eav.Data.ContentTypes;
using ToSic.Eav.Data.Raw;

[ContentType(
    Name = "MetadataTargetTypes",
    Guid = "52c96a68-c791-439f-a154-7c46c1bfa0d9",
    Description = "Metadata target type",
    Scope = "System"
)]
internal sealed record MetadataTargetTypeRaw(
    int Id,
    [property: ContentTypeTitle] string Title,
    string NameId
) : IRawEntityAutoConvert;

Then return these records from the DataSource:

public MetadataTargetTypes(Dependencies services)
    : base(services, logName: "Ds.MetaTg")
{
    ProvideOutRaw(GetList);
}

private IEnumerable<MetadataTargetTypeRaw> GetList() =>
    service.GetItems()
        .Select(item => new MetadataTargetTypeRaw(
            Id: item.Id,
            Title: item.Title,
            NameId: item.NameId
        ));

That is all that is needed in the common case.

What Happens During Conversion

When the stream is requested:

  1. GetList() loads the raw records.
  2. ProvideOutRaw(...) passes them to the data factory.
  3. Public properties such as Title and NameId become entity fields.
  4. The resulting entities are returned through the query API.

The entities are temporary query results. They are not saved as app content.

Some property names have a special meaning:

Property What happens
Id Used as the entity ID
Guid Used as the entity GUID
Created Used as the creation date
Modified Used as the modification date

These properties do not appear again as normal fields. If no ID is supplied, the factory normally creates one automatically.

Creating a Good Raw Model

Use these simple rules:

  1. Prefer an internal sealed record.
  2. Implement IRawEntityAutoConvert.
  3. Add [ContentType] with a new, stable GUID.
  4. Mark the main display property with [ContentTypeTitle].
  5. Only add properties that should be returned to the UI.
  6. Only provide an ID or GUID when the source has a meaningful one.

For positional records, use [property: ContentTypeTitle] as shown above.

Keep the values simple: strings, numbers, booleans, dates, and similar scalar values.

Attributes on Raw-Model Fields

The converter inspects public properties and infers normal scalar field types from their C# types.

Attribute Purpose
[ContentTypeTitle] Marks the entity title; shorthand for [ContentTypeField(IsTitle = true)].
[ContentTypeField(...)] Changes the generated field name, type, title status, description, or work-in-progress input type.
[ContentTypeIgnore] Excludes a public property from the generated content-type definition.

ContentTypeIgnore only changes the generated definition; automatic raw conversion still reads public properties as values. If a value must not be returned, do not expose it as a public property or use a custom converter.

ContentTypeField has Name, Type, IsTitle, Description, and InputTypeWIP settings. Usually only Type is needed: it overrides the inferred EAV ValueTypes value. Common overrides are Hyperlink, Entity, and Object; use Entity for relationships and Object for nested JSON.

On normal properties, place the attribute directly on the property:

[ContentTypeTitle]
public required string Name { get; init; }

[ContentTypeField(Type = ValueTypes.Hyperlink)]
public required string Url { get; init; }

[ContentTypeIgnore] // Only omitted from the generated definition
public string SchemaOnlyValue { get; init; } = "";

For positional records, target the generated property:

internal sealed record ExampleRaw(
    [property: ContentTypeTitle] string Name,
    [property: ContentTypeField(Type = ValueTypes.Hyperlink)] string Url
) : IRawEntityAutoConvert;

Deep Data with ValueTypes.Object

Mark nested DTOs, dictionaries, lists, and arrays as ValueTypes.Object when they should remain deep data in the JSON response:

[ContentTypeField(Type = ValueTypes.Object)]
public required IEnumerable<ParameterRaw> Parameters { get; init; }

[ContentTypeField(Type = ValueTypes.Object)]
public required IDictionary<string, object?> Security { get; init; }

Object keeps the property as an object-valued entity field. It is not recursively converted into more 2sxc entities; the JSON serializer emits the contained values as deep JSON. An Object field automatically enables unknown/object values for that conversion. For attributed IRawEntityAutoConvert models, use the attribute instead of setting AllowUnknownValueTypes manually.

Use the factory option below for dynamic data with no attributed property schema, such as a RawEntity with runtime-defined fields:

ProvideOutRaw(
    GetList,
    options: () => new()
    {
        AllowUnknownValueTypes = true,
    });

Other Ways to Return Raw Data

There are three less common alternatives.

new RawEntity()

Use RawEntity when the field names are dynamic or the values are already in a dictionary:

new RawEntity
{
    Id = app.Id,
    Values = new Dictionary<string, object?>
    {
        ["Name"] = app.Name,
        ["Folder"] = app.Folder,
        ["IsHidden"] = app.IsHidden,
    },
};

In this case, the DataSource often supplies the type and title names:

ProvideOutRaw(
    GetApps,
    options: () => new()
    {
        TypeName = "App",
        TitleField = "Name",
    });

A Custom IRawEntity

You can create your own class implementing IRawEntity. It must provide Id, Guid, Created, Modified, and a Values dictionary.

This is rarely necessary because RawEntity already implements it.

IRawEntityConvertible

Use IRawEntityConvertible when conversion needs custom logic, for example:

  • removing or renaming fields;
  • only adding an expensive value when requested;
  • creating relationships between returned entities;
  • performing a highly optimized conversion.

Its GetConverter() method returns a converter which creates a RawEntity. Keep this method as an explicit interface implementation so it does not appear in the serialized model.

See AppStackDataRaw and UserModelRaw in the examples below.

Which Type Should I Choose?

Situation Use
Normal typed record IRawEntityAutoConvert
Dynamic dictionary of fields new RawEntity()
Reusable custom raw container IRawEntity
Special conversion logic or relationships IRawEntityConvertible

IRawData is only the shared marker interface. Do not implement only IRawData, because it does not explain how the object should be converted.

Output Streams

ProvideOutRaw(GetList) creates the default stream. Use name for additional streams:

ProvideOutRaw(GetItems);
ProvideOutRaw(GetWarnings, name: "Warnings");

The callback remains lazy: GetItems() is called when the stream is requested, not while the DataSource is constructed.

A very simple DataSource can instead override its default output:

protected override IEnumerable<IRawData> GetDefault() => service.GetItems();
