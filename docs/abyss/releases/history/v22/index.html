Version 22

2sxc v22.00.00 (2026-08-??) PREPARING / WIP

Models APIs 💃🏼

The Models API was officially released before, but not really communicated, so we believe it's not used yet. During our first attempts to use it we determined that it needs some more love, so we reworked it. This is kind of a breaking change, but we believe it's not used yet, so it should be safe to do.

  1. 💃🏼 Introduce ToModelOptions for type-name and null-conversion options
  2. 💃🏼 Standardize exceptions thrown for better diagnostics, incl. missing empty constructor etc.
  3. 💃🏼 Ensure that interface specs are prioritized to concrete implementations if the interface was used in the ToModel<I> method
  4. 💃🏼 On interfaces which are used for both models and Raw Data, also respect the Name of the [ContentType] attribute
  5. 💃🏼 Change derived class to be on the IModelFromEntity<Concrete> instead of the [Model...] attribute
  6. 💃🏼 Create / test many combinations of ToModel / FirstModel etc. - also with/without factory
  7. 💃🏼 Introduced IFieldSettingsGeneral, IContentTypeDetails, IPaging, IViewConfiguration models
  8. 💃🏼🧪 Created ca. 500 unit tests
  9. 💃🏼📖 Major documentation for models use - still WIP

Raw Entity Conversion APIs 🦴

  1. 🦴 Created / improved ContentTypeFromCode generation system as it's the foundation of type-names for models
  2. 🦴 also renamed [ContentTypeSpecs] to [ContentType] and introduced [ContentTypeUse] for referencing other content-types
  3. 🦴 Changed base object RawEntity to be a record
  4. 🦴 Created fallback RawEntityClassic for class based data - not sure if we'll keep this though
  5. 🦴 Reworked Object-To Dictionary APIs to reduce the code needed
  6. 🦴 Major rework in general...
  7. 🦴🧪 Created ca. 400 unit tests
  8. 🦴📖 Documentation for this Coded Content-Type Definitions new v22 / Coded Data Creation of Entities WIP v22

Other

  1. ⚠️ a vCard API extension was removed. We believe it has never been used since v20 where the folders changed, so we don't think this will affect anyone.

Copilot Enhancements ✈️

  1. ✈️ Data Copilot should not generate Ephemeral fields
  2. ✈️ Data Copilot better detects entity-fields and the expected data type within
  3. ✈️ Data Copilot auto-generate models on changes (WIP / BETA) - ATM for changes in ContentType (like name) and for changes in field names

App Enhancements

  1. Changed all apps to build with Vite (TODO: verify)

Bugfixes

  1. 🪲 MailService threw exception when not providing attachments
  2. 🪲 Compiling code fails to pick up config.json on the fly, so installing Radmin doesn't work until restart
  3. 🪲 Bug exporting apps with very long names
  4. 🪲 Quick-Dialog had timing issues, so it sometimes didn't appear as expected

Toolbars

  1. ✏️ Toolbars opening the edit dialog for only an entity-field works now
  2. ✏️ Toolbars targeting a entity-field for add-new can now specify the content-type to use for the new entity (New(contentType: '...'))
  3. ✏️ Improve icon assignment - especially for entity-fields with multiple target types to pick up the right one from the configurations

Oqtane 🩸

  1. 🩸 Support the new Multi-Language system of Oqtane (note that it's still very buggy, because the Oqtane implementation is buggy)
  2. 🩸 Improve ImageFlow in edge cases
  3. 🩸 Introduce Linux support (and test on Linux), preparing for container use as well and multi-DB

Internal and Code Hygiene
